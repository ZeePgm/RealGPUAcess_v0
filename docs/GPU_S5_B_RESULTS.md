# S5-b 固定计算时间验收结果

2026-11-01，批次 `output/gpu-s/20261101-s5b-002/`。**S5-b通过，同一最终执行器下S5-a复验通过，S5整体通过。S6尚未执行。** 未改变B2阈值、模型参数、Host／Device实现、内容身份或指标公式。

## 条件、分段和依据

沿用已验收的Qwen3-0.6B-F16、主输入44 tokens、贪心解码、原生F16 KV、M2有效登记10240B／注册12288B、冻结H0，输出上限依次2和8。每例独立Session，普通写初始化完成后取请求t0。源码、执行器、配置、依赖构建身份和输入哈希均保存在批次中。

原交接文档第4节要求保留首段、相邻访问间工作及每token尾段，互斥且不漏计；第6节要求先成功完成依赖，再执行消费者，尾段只结算当前token之前未计工作。S系列方案第7节据此预先规定：每个已定义的GPU工作或必要传输段只推进一次1000ps。**1000ps是人为功能测试值，并非实测GPU耗时；按段而非按kernel或回调计数是本实验的实现选择。**

最终执行器 `gpu_s_segmented` 将生产工作划分为以下互斥窗口：

| 窗口 | 边界及推进位置 | 计时规则 |
|---|---|---|
| gap | 每步执行开始／上一节点及其验证快照结束，到下一节点的门控之前；全设备同步后关闭 | 有GPU活动则推进一次1000ps；空窗口为0 |
| node | HBF依赖成功之后，到该节点执行并全设备同步完成 | 同窗口内一个或多个kernel、D2D或memset合并为一段，推进一次1000ps |
| tail | 最后节点及其验证快照结束，到当前输出回传且GPU同步完成 | 每token一段，发生在token可交付时刻之前；不重复添加整次请求tail |
| verification | 为数值核验额外导出的快照拷贝，单独同步和记录 | 明确排除，不推进模拟计算时间；timing模式不产生这些拷贝 |

返回全部节点的调度回调仍使每次执行一个节点；额外的`cudaDeviceSynchronize`覆盖当前唯一可见设备的所有stream，在门控前清空先前GPU工作。CUPTI在每个窗口末尾flush，记录kernel、memcpy、memset及其提交API关联ID；每个非空生产窗口对应一次`advance_compute`。空视图节点保留事件但不制造计算时间。

本次每个token恰有 **735个有效段：1个输入gap、733个节点工作段、1个输出tail**。输入前两个回调没有GPU工作，首个非空gap位于第三个回调之前。735是本次轨迹的测得段数，不是预设常量，也不保证其他模型或输入仍相同。

## 实测验收结果

以下时间均为**固定计算输入＋未校准H0后端的模拟功能结果**，不是原生GPU墙钟性能。

| 案例 | 实际输出 | 有效段数 | 总计算ps | 总等待ps | TTFT ps | 每个ITL／TPOT ps | 最大守恒残差ps |
|---|---:|---:|---:|---:|---:|---:|---:|
| 零计算复验 | 2 | 1470 | 0 | 755776 | 487788 | 267988 | 0 |
| 固定1000ps | 2 | 1470 | 1470000 | 755776 | 1222788 | 1002988 | 0 |
| 零计算复验 | 8 | 5880 | 0 | 2363704 | 487788 | 267988 | 0 |
| 固定1000ps | 8 | 5880 | 5880000 | 2363704 | 1222788 | 1002988 | 0 |

独立审计逐条重建计算推进和访问等待的顺序、前后tick及每token累计值，而非只核对最终总和。首token为 `735×1000+487788=1222788ps`；后续每个间隔为 `735×1000+267988=1002988ps`。零计算与固定计算的实际等待恰好相同，这是本批次结果，不作为通用假设。

8输出序列为 `[32,6366,5711,4938,311,3553,323,17179]`；2输出为其前两个。均因输出上限结束，没有额外预测步。未观察到自然EOS；N=0/1、EOS和表错配的指标边界仍引用S1合成测试，不将其冒充真实GPU EOS结果。

8输出生产轨迹含 **6112个kernel、276次memcpy、54次memset**。memcpy细分为72次H2D、8次输出D2H、196次D2D。原诊断中不完全位于节点内的80次传输，现分别纳入8个输入gap和8个输出tail。核验模式额外3608次快照D2H单独排除；2输出排除902次。全部活动恰好归属一个窗口，CUPTI无丢失；不同窗口的GPU活动不重叠。

CPU独立参照重新运行，2／8输出分别比较343／1369个数组，native、零计算HBF、固定计算HBF均通过冻结的B2分类工程判据。native/HBF完整logits、有效快照及原始事件逐项一致；GPU KV发布舍入检查通过。verify/timing的logits、输出、原始事件和逐段提交操作一致；同样逐段比较了native与零／固定HBF的kernel名称、拷贝方向／字节数和提交顺序。

两个选区每步均经完整Global/64B片段及内容成功核验，父访问完成时间等于其最后完成的子Global；消费者提交发生在成功门控后，所有Session正常关闭并排空。8输出共24个读Global、1280个64B读片段。

## 时间戳诊断与证据等级

先行批次 `20261101-s5b-001` 在校准输入检查中发现：CUPTI投影到CPU时间域的部分GPU起点，早于紧邻的CPU窗口起点，最多10125ns。该批次未获验收，原始数据、源码和失败记录完整保留。

最终实现没有用放宽时间阈值掩盖这一现象，而是增加提交API的`correlationId`证据：每个GPU活动均能关联到窗口内成功的CUDA提交调用；该调用先于窗口末尾成功返回的全设备同步；门控位于先前窗口同步完成与消费者窗口开始之间。因而依赖关系由真实提交和同步完成建立。GPU活动时间戳用于活动时长和GPU活动之间的重叠检查，CPU/GPU投影偏差单独保存在`segment-audit.json`，不作为直接跨时钟的因果证明。最终批次部分运行仍观察到此偏差，未删除这些记录。

这一同步分段是当前串行门控模型的实现，增加了插桩和同步。S6须按最终二进制、timing模式另行冻结采样协议，评估实际活动时长、分辨率、波动与插桩影响；不能将本轮每段1000ps、CPU窗口长度或进程墙钟充作G1实测表。
