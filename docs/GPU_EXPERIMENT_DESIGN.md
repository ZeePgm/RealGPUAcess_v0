## 0. 设计依据与要回答的问题

本文用三类依据约束设计：**R=原文明确要求；L=为回答问题而作的逻辑推导；C=可调整的工程配置**。C 必须说明用途与选值依据，不能冒充原文要求或已经充分的统计设计。B 表示正式实验前必须完成论证与冻结的事项。

原文第1节要求回答四个问题：哪些权重访问经过 HBF；等待是否改变 token 完成时间；数值是否保持一致；结果依赖哪些假设。主线因此为：G1 测量真实计算 → 冻结相同计算表 → G2/G3 控制变量对照 → 数值与行为审计 → 三张图解释影响。

## 2. 推荐方案与实验边界

首轮以 S 系列完成最小交付。A 是按改动影响选择的整机回归，不是新增的必做性能系列。**主图来自 S；A 不与 S 拼接成一个时钟。**

| 系列 | 路径与目的 | 计时/解释 |
|---|---|---|
| S：同步权重门控 | 当前 llama.cpp CUDA + 原生 F16 KV → 实验适配器 → 现成 TensorAccessBridge → Session/Host/Device | 固定 GPU 计算表 + 串行选区等待；完成原交接的 G1/G2/G3 与三张主图 |
| A：按需整机回归 | 原 native/paged bypass/modeled，保留 PTX/warp 访问、分页 KV、有限 frames、共享 Session | 检查被改动影响的既有能力；只报告实际记录的指标，不要求为A另建性能实验 |

S 系列选择只读桥是因为交接文档要求同步、无重叠、固定计算输入，且它已提供所需接口。A 系列的异步可变共享 Session 不需要整改。首轮不把 KV 写回、预取、热模型和文件 backing 加入 S 系列，避免把这些费用解释成权重等待；它们仍是工作区已有功能，不是被判为不支持。

S 系列权重仍在 GPU 显存；HBF 初始化和读取的是符号内容。它只能说明该同步门控模型中选定范围的等待影响，不证明真实 NAND 字节搬运、权重显存节约或校准后的硬件吞吐。

依据 R：第3节、第7节、第8节结论边界。依据 L：权重等待、KV换页和CPU软件成本若同时变化，无法单独归因；S固定KV策略和其他条件。该选择限制结论范围，不表示工作区没有分页KV能力。

## 3. 输入、映射和工作量

### 固定输入

- 模型：Qwen3-0.6B F16 GGUF，F32 norm、F16 KV；由当前 profile generator 检查实际元数据、GGUF 与 conversion 哈希。不凭模型名称推定形状。
- prompt：现有 `adapters/llama_cpp/prompt.txt` 原始 UTF-8，冻结实际 token IDs；不隐式套 chat template。
- 单请求、单序列、greedy，最多 8 个非 EOS 输出（R）。`n_ctx=512、n_batch=256、n_ubatch=256` 只是当前框架的候选容量配置（C），正式值需在访问语义冻结时登记；验证P不超过实际n_batch，P+8不超过实际n_ctx。
- 原文batch=1约束请求批量；llama.cpp的n_batch/n_ubatch表示token处理容量，不是并发请求数。保留批量prefill不等于可以假定其权重流量按prompt长度重复；也不与旧逐位置prefill性能直接比较。
- CUDA graphs/flash attention 关闭，线程和精度固定。S 系列在门控边界显式同步依赖，禁止跨门控边界重叠；同一 kernel 内的 CUDA 并行保留。
- 模型、GPU、工具链和本地 profile 已在S0核实，实际身份随结果保存；后续更换环境或输入必须重新核实。缺输入就报告缺项，不自动换模型或 CPU 降级。

### 清单

令 H=hidden、F=ffn、L=min(10,layers-2)。以下是候选清单（L/C）：尽量复用已有选区，并覆盖原文要求的8KiB、多tensor和非零偏移。只有原始事件能表达真实消费者涉及的相应源范围，才可据此正式冻结清单。若切换清单改变了算子拆分或事件序列，则不能沿用旧表，须重新验证并测量。

| 清单 | 有效源范围 | 地位 |
|---|---|---|
| M1 | `blk.L.ffn_norm.weight` [0,4H) | S3单区域闭环起点；S4在其基础上增加down区域 |
| M8 | `blk.L.ffn_down.weight` offset=0、bytes=8192，确认在 tensor 内 | 原 8KiB 语义回归；不声称重现旧 q_proj 实验 |

### B1：先冻结访问语义，再推导流量

撤销v2中“prefill处理R行就展开为R次权重读取”的规则。原文没有这个要求，批量计算的行数也不能证明实际权重读取次数；称其保守不能代替依据。

正式实验前登记 `access_semantics.json`：实际hook位置、消费者操作/launch、源tensor及offset/bytes、position或position-range、调用次数、是否有可观测复用，以及本模型刻意不包含的cache/物理load行为。用小型真实CUDA案例和独立范围审计核对这些记录，确认hook能在依赖计算之前阻断。不能从图metadata或输出行数直接推定访问已经发生。

若采用算子输入范围作为逻辑访问，必须明确说明“每次真实消费者调用的输入范围”及批内复用假设，报告逻辑流量；若采用PTX/warp访存事件，则保留其实际调用与地址范围。两种粒度不能相互替换计数。选用哪种粒度须先证明与同步桥、GPU测量边界相容，再写入冻结合同；若需要新同步/算子拆分，G1/G2/G3必须共同采用并重测。

验收条件（R第5/6/8节，L为其工作量含义）：每个事件有消费者与源范围依据，重复访问不丢失也不人为复制；独立审计可重建访问交集；改变选区只过滤同一事件序列。无法建立该合同就停止正式采集，不用R倍展开补齐工作量。

所有相关权重输入事件在过滤前稳定编号；一个回调命中多个区域，计算推进一次，交集逐个串行完成。hook 必须位于消费者实际 CUDA 发射之前；图构建 metadata 回调本身不保证执行边界，不能直接当作“已访存”。发生失败时不发射消费者。

覆盖分别统计：去重注册有效字节、触达区间并集、累计有效访问字节、填充、Global流量、64B命令流量（R第5节）。例：H=1024/F=3072时M2有效10240B、注册12288B，这只说明存储布局。累计流量必须从B1冻结的实际事件交集逐次求和，删除v2中按P+N-1直接乘权重大小的通用流量公式。P+N-1仅在无EOS、无额外步骤时描述处理的token位置数，不证明权重访问次数。EOS检测步单列。

## 4. 冻结后端配置

R第8节要求固定一组参数；R第5节要求容量不足报错、禁止静默扩容。下面的数值取已有源码配置作为起点（C），依据是复用已测试契约并减少变量，不是原文指定或硬件校准。正式配置必须通过resolver、初始化覆盖、容量和前进性检查后冻结；未通过则登记失败及新的配置版本。

S 系列采用 `tests/incremental_bridge.cpp::config()` 的已存在配置作为起点：geometry={1,1,2,16,64,1}、capabilities={256,4,false,true}、MOCS=256、timeout=10000000ps、Burst4096、AllRegular、resident_fragments=256、FCFS Host/NAND，Global chunk=4096B。所有值经公开 resolver 校验，完整有效 INI 随结果保存。

介质参数沿用当前源码示例：sense=100000ps、program=500000ps、erase=1000000ps、cache=100ps；read window=10000ps、threshold=32；Grade1 链路、控制等效字节各16B、请求/响应固定延迟各100ps。ingress=16/16384B，egress=8/512B。**这些是未校准模型参数。** 不为得到明显差异擅自调大它们。

每个HBF联合配置从新的Session开始；通过 initialize 普通 Global 写按合法页序完成全部注册范围。逐次检查 success，初始化耗时和 program/erase 单列；t0 在初始化之后。保留合法初始化后的设备状态，不用私有接口“清 cache”。所有覆盖清单使用同一设备几何与预算，容量不足直接报告。纯记录驱动的G2可不创建Session，不产生NAND流量；G2/G3比较各自相对请求t0的时间，而不是初始化后的绝对Tick。

请求级events ceiling=10^7、同Tick/round guard各100000、无有限模拟时间上限、单进程墙钟限额3600s，均是控制首轮软件运行成本的初始预算（C），不保证一定足够，也不是性能指标。准备阶段根据小案例事件量和内存成本评估，再登记正式值及理由。故障/限额测试用独立配置；运行中不静默增加预算，超限样本保留。A继续使用其profile预算。

## 5. 三种时间和计算表

### 原生真实测量

S-native与S-HBF使用相同CUDA算子拆分、精度、原生KV和事件边界，HBF开关只控制依赖等待（L：控制变量；R第6/8节）。模型加载和符号初始化在请求计时外，每次重置请求/KV。

预热3次、测量10次仅作为准备阶段的初始工作量（C），撤销其固定验收含义。正式采集前登记采样协议：最大预热/采样预算、批次样本量、稳定性检查窗口和允许波动、低分辨率段处理、停止条件。稳定性要依据连续批次的请求GPU工作和关键段分布评估，并保存warm-up与原始样本；达不到预登记判据则增加到预登记上限或标为不稳定。不能因为恰好完成3/10次就认定充分，也不能为得到预期HBF差异而选择停止点。

原文第4节允许CUDA event或等价GPU时间戳（R），不限定必须使用CUDA event。当前S6采用CUPTI的真实GPU活动起止时间（C），在S5已审计的互斥gap/node/tail窗口内取kernel、memcpy、memset时间区间的并集，跨stream重叠只计一次，窗口无活动则为0。保留首个访问前、未选中回调之间、prefill边界和每token尾段，必要传输与kernel原始记录分列，验证快照单独排除。

该口径表示GPU活动工作量，不包含段内主机发射空隙；各段首尾活动跨度包含空隙，不能与活动并集或真实请求时间混用（L）。若今后选择包含设备空闲的另一种段时长语义，必须先声明模型边界并形成新的测量版本。任何计时区间均不得纳入CPU后端等待、核验I/O或自旋等待；原设计仅写CUDA events的表述由本段替代。

CUPTI GPU/CPU时间投影不能直接用来判定门控因果关系。沿用S5-b的提交API correlation关联和全设备同步证据验证活动归属与依赖顺序；GPU活动时间戳用于工作时长及活动重叠检查（L，已通过S5-b/S6覆盖审计）。

按相同采样协议配套测量不启用细粒度event/快照的native请求（L：识别插桩成本），保存单调主机时钟的请求和token可交付时刻，报告与段测量运行的差异。必要的logits取回/采样保留，关闭额外核验导出。重复次数由协议登记，不另固定10次。当前已完成该低插桩对照；每次为新进程，3对预热主要暖机，不代表同一上下文复用的稳态服务测量。

### S6最小目标的验收与测量限制

原采样协议在10对时通过总GPU量和各token工作量的聚合规则（相邻5样本批次中位数漂移≤10%、批次极差/中位数≤30%）。这些是工程筛查配置，不是逐段精度保证；原始协议及数据不改写。

用户明确要求回到原始最小实验目标：原文第4/8节要求可复用实测计算记录、完整边界和同表G2/G3，不要求每个短段达到独立稳定性阈值。关键短段相对波动大及亚微秒精度未知不阻断这一固定轨迹机制实验；据此给予范围限定的S6 pass。这是用户授权的验收范围澄清，不是补做了预登记精度验证。

所有时长、短活动、波动和分辨率标记保留，且不置零或平滑。输入/输出gap/tail占总GPU活动量约0.51%–0.63%；小于1µs活动时长之和占约1.79%–2.10%（可含重叠），两者都不是测量误差界限。

后续只在这一固定轨迹、配置和选区下解释模拟等待影响及时间守恒。计算表C的测量波动不会作为不同输入混入同一G2/G3配对，但改变C可能改变后端状态与等待，所以不能将单表结果外推到所有轨迹或真实HBF硬件。原生请求及采集成本仍单列。

若研究目标扩展到单短段精确耗时、微小真实性能收益或跨轨迹预测，再按目标效应预登记不确定性/采样规则，优化观测扰动并以新样本验证。若改同步、hook或算子边界，须补做受影响S2—S5验收。该精度专项不再作为当前最小实验的前置阻断。完整依据与验收标注见[限定验收](GPU_S6_MINIMUM_ACCEPTANCE.md)。

### 固定计算输入

R第6节要求冻结记录、说明取值方法，未指定逐段中位数。正式采样保存每次完整表；主表建议选取“GPU工作总量最接近完整请求样本总量中位数”的那一次完整记录，平局按采样顺序取首个（C/L：具有代表性且保留同次请求段间关系）。该规则在采样前登记，不按G3效果挑选。若另用逐段中位数，只作为明确标注的组合表敏感性对照，不能冒充某次实测请求。

G2/G3必须使用同一张已冻结表（R）。当前最小实验使用新限定验收目录中的同一sample-3表；旧目录候选表及旧资格记录仅作历史溯源。另可对全部有效完整样本表做配对重放以说明计算波动（L，可选），不能挑选有利样本，也不把8个token包装成可靠p99。原始GPU测量波动与固定表模拟的确定性分开报告。

段键为 request/phase/execution-position或position-range/op-occurrence/segment ID；不能只按 tensor 名索引。header 绑定模型、prompt IDs、生成配置、算子/精度、源码、二进制与事件序列哈希。清单变化只允许筛选同一事件序列；改变 batch、精度、CUDA 算法或输入必须重测。

单位转换随测量来源声明：CUDA event的ms×10^9后round-to-nearest转整数ps；当前CUPTI的整数ns×1000精确转ps。两者均检查非负、有限及溢出；记录测量分辨率和不确定性，不能从文件存储单位推定准确度，短段标记且不人为加Tick。可合并不跨访问/token 边界的段，禁止为得到非零数越界合并。

执行顺序：`advance_compute → access各交集并检查最终成功 → 后续计算 → token事件`。access 的 compute 参数设0，避免已经推进的计算再次计费。零段沿用同 Tick 续体；首段与每 token 尾段均只计一次。缺段、错序、重复、哈希不符立即拒绝，不能自动退回固定1000ps。

### 指标定义

- t0：已加载、已初始化、已分词后，开始请求推理。
- prefill_finished：prompt GPU 工作完成；token_emitted：采样已确定可交付 token ID，位于文本解码/打印之前。二者语义不同。
- TTFT=t1-t0；ITL_i=ti-t(i-1)；TPOT=(tN-t1)/(N-1)。N=0 的 TTFT、N<2 的 TPOT 为 null。
- EOS 不计输出 N；保存 raw EOS token 与独立结束事件。输出上限后不执行预测下一枚 token 的额外工作。当前 runner 已无该多算问题，保持它，而不是照搬旧24位置要求。
- 每个 S 模拟 token 区间必须满足：总长=GPU计算+纳入模型的GPU传输+HBF等待，整数 ps 残差为0。
- CPU sampling/调度等未建模部分明确列出；真实 native 请求墙钟与 modeled 组成不同，不能直接用二者相除声称 slowdown。
- 加载、初始化、核验导出、后端运行墙钟、最终排空另列。EOS 检测尾段可计入请求结束，但不能回加到最后一个用户 token 的时刻。

依据R：第6/7节。依据L：在相同token序列、计算表、事件序列和同步无重叠模型下，到token i的累计时刻满足 `T_i(G3)-T_i(G2)=此前累计选区等待`；ITL差值等于对应token区间等待，TPOT差值等于首枚之后等待总和除以N-1。比较时先减去各自请求t0，避免不同初始化时刻造成差异。若违反这些关系，先查遗漏、重计或其他推进来源，不能解释为硬件波动。该核对关系不用于A的异步模型。

## 7. 数值核验与拟修改范围

### B2：CPU参照与误差合同

**2026-11-01新版工程合同**：在本轮Qwen3模型及固定执行条件内，logits相对RMS/最大归一化元素误差上限为0.001953125/0.0078125；hidden、Q/K/V计算结果为0.00390625/0.015625；F16 KV存储为0.00390625/0.03125。每个数组须同时满足两个阈值，另要求token、EOS、结束原因及位置一致、形状匹配、数值有限，GPU自身有效KV发布逐位正确。公式、选择依据、校准和限制见[新版S2结果](GPU_S2_B2_V2_RESULTS.md)；这些预算是用户要求采用的工程验收条件，不是数学前向误差上界。

R第4节任务6要求独立CPU/native/HBF多token对照和事先声明阈值，没有指定CPU工具或具体容差。当前native/bypass/modeled不能替代独立CPU参照。

优先复用已有、可独立验证的CPU数学参照。NumPy或其他CPU框架均为工具选项（C），不预设必须重写全模型。必须核对同一模型修订、GGUF实际权重值及转换关系、token IDs、Qwen3 RoPE/QK norm/GQA、KV类型及舍入、greedy/EOS，确保参照不复用被测CUDA实现。旧FP32执行器或另一精度的CPU输出不能未经说明直接作为F16路径的误差基准。

撤销v2的CPU logits `max_abs<=0.2、RMS<=0.025` 及hidden/KV固定容差。前者来自其他GPU比较路径，后者没有充分的本案例误差依据，均不能自动推广。

正式实验前形成 `numerical_contract.json`：

1. 明确每类比较数组的精度、形状、缩放、舍入位置与归约差异，声明可接受误差要保护的数值性质。
2. 根据上述差异给出误差边界的分析或可核验参考依据；用与正式prompt分离、预先登记的校准案例检验CPU参照及误差模型。校准案例不进入正式性能结论。
3. 冻结logits、hidden、KV各自的max/RMS、绝对/相对误差或其他明确判据，并保存理由、校准样本、版本和哈希。不能只按观察到的最大误差加余量，就声称阈值具有充分依据。
4. 正式案例tokens及EOS/结束原因一致、数组有限且形状匹配；不同执行顺序的CPU/GPU按冻结合同核验。失败先查实现、精度和参照，不能根据正式结果放宽阈值。若误差合同不成立，应停止正式性能结果解释，重新形成有独立依据的合同和新实验版本。

未完成B2就不能宣布三方数值验收通过。合同准备是实施后的前置工作，不表示本设计审查轮已经执行了校准。

S-native/G3及启用CUDA核验的G2，在相同CUDA算法与顺序下，逐token logits与关键快照要求逐字节相同（R第4节）；verify/timing模式token和最终logits也须一致。纯记录驱动G2只核验与冻结事件/token记录匹配，不声称它重新计算了数值。核验模式保存每位置选中层前后hidden、各层新K/V、全部输出logits；计时模式关闭额外D2H快照与导出。CPU/native/G3不能只比较最后一个token。

拟修改集中在当前 integrated runner/weights/profile、实验适配/测量/分析脚本及对应测试。链接现成 `HBFEventLab::tensor_bridge`；不新增 Host/Device，不改其调度、内容身份、重试或时钟。新增应用语义放实验层，token 不进入核心。通用配置/IO/来源记录优先复用 `third_party/HBF-EventLab/experiments/common/` 与当前 build identity 工具。

现有 runner 仍限制输出2..448、早期EOG抛错、process_wall_ms在采样前结束；新实验入口需支持0/1/正常EOS及可交付时刻。建议独立实验模式或 runner，保留旧验收入口的严格固定长度行为。

## 8. 必须通过的契约审计

1. 无 CUDA 时间例：10μs计算+20μs等待+5μs计算产生token1，TTFT=35μs；再3+7+2μs产生token2，ITL/TPOT=12μs。
2. 首段、末段、未选中回调、多区域同回调、prefill批量段、N=0/1、EOS、零计算、表缺失/重复/错序/输入不匹配。
3. 多区域、非零offset、尾填充、别名去重、跨区交集、非法重叠/越界、容量不足、未选区不提交。审计从原始回调和清单独立求交，验证源偏移→区域偏移→Global，不照抄适配器汇总。
4. 合法完整DLU初始化，同block同content；所有Global final结果归属明确。父完成时刻=所有子Global最终完成最大值，完成与成功分别检查。
5. 容量背压保留未登记范围，通知后重查；命令尝试失败不直接等于Global失败；Host retry/replay仍由原Host处理。
6. 最终依赖失败立即禁止消费者发射。正常失败停止未登记后缀并排空已登记工作；严重Session错误/限额保留未决项，不能宣称已排空。
7. `finish`关闭来源并验证Host/Device排空；A系列还应区分end_stream的临时排空。初始化program与应用writeback分开，logical snapshot pages与host_replay_commands分开。
8. full audit/lean timing两种观察模式结果一致。精简模式不声称做了完整事件审计；CUPTI dropped、文件缺失、日志截断使完整审计无效。

实际顺序及失效后回退规则以分步设计的S0—S10为准。B1/B2在S2完成；S3/S4/S5分别验证单区域单输出、多区域单输出、多区域多输出；S6前冻结采样协议。任何前置条件未成立，不进入正式性能采集；修改执行器时重做受影响验收，不能直接复用旧版本证据。
