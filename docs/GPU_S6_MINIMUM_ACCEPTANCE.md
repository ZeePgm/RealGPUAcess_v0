**结论：S6在“原始最小固定轨迹机制实验”范围内通过，可以进入S7/S8。单个短段的精度资格仍未建立。**

依据原交接文档第4节与第8节：最小目标是提供真实GPU时间来源的可复用计算记录、完整请求/token边界、三方数值与访问依赖证据，并让G2/G3使用同一计算表。原文要求承认极短区间分辨率限制，没有要求每个短段达到某一重复稳定性阈值。此前将关键短段稳定性缺口作为整个最小实验的阻断项，超出了该目标所需条件。

用户本轮明确授权在不影响原始最小目标时定义忽略波动的验收标注。本次据此调整验收范围，属于**事后明确研究目标与结论边界**，不冒称是预登记的新精度验证。旧批次`20261101-s6-001`的inconclusive、协议及候选表均保留；新批次`20261101-s6-minimum-acceptance-001`记录范围限定的pass，并冻结同一sample-3表，实测时长和样本选择完全不变。

## 为什么可以继续最小实验

固定表C确定后，G2/G3逐段复用相同C，选区等待及token时间守恒由确定性模拟和真实消费者门控审计验证；重新运行GPU测得的局部波动不会作为另一个计算输入混入其中。每token应检查`T_G3 - T_G2 = G3累计实际HBF等待`。HBF状态和等待仍可能依赖C的推进位置与时长，所以结论必须限定在该固定轨迹及配置，不能宣称对其他实测轨迹都成立。

10个已有样本中，输入gap与输出tail合计占总GPU活动量约0.51%–0.63%；小于1µs活动时长之和约占1.79%–2.10%。后者可能重复计入重叠活动，不是并集占比，更不是测量误差上界。这些比例仅解释相对波动大的局部段在当前总工作量中的规模；即使它们较小，也不能据此保证硬件性能误差很小。

## 验收标注

- **验收名称：** `minimum_fixed_trace_mechanism_experiment`，S6状态`pass`，适用后续S7/S8同表控制变量实验。
- **保留硬性条件：** 真实GPU时间来源、每段归属/完整性、无重复时长、数值正确性、事件身份、源范围/内容、成功依赖、token边界、错误停止和最终排空。S7/S8尚未执行，其条件仍须实际验收。
- **本范围不设阻断：** 单个短段相对波动大；短于1µs活动的精度尚无独立保证。这些记录均保留为限制，不删除、不置零、不人为平滑，也不放宽数值合同。
- **允许结论：** 在这一完整实测固定轨迹、选区和未校准后端参数下，同步访问等待怎样改变模拟token时刻，以及实现是否满足时间守恒和访问因果关系。
- **不允许结论：** 单段测量达到已证明的微秒/亚微秒准确度；小幅模拟差异等于真实硬件可观测收益；精确预测真实HBF硬件或所有native运行。

使用表：`output/gpu-s/20261101-s6-minimum-acceptance-001/compute-table.json`，header的`frozen_G1=true`且标明限定范围。新验收记录绑定旧协议、旧stage和旧表哈希，复核了10次样本的段内GPU区间并集和整数ps换算；新旧表的segments完全一致。仓库摘要见[验证记录](validation/gpu-s6-minimum.json)。

## 哪些进一步目标会受到影响

若目标变成单个短算子/传输的精确耗时、很小的性能改善是否在真实运行中可见，或跨多次实测轨迹的稳定性能预测，这些波动和分辨率限制就会影响结论。解决方案是另设精度/敏感性实验：先按目标效应定义可接受的不确定性与停止规则，降低逐窗口flush等扰动，核验时间戳分辨率，必要时在不跨依赖/token边界的范围内合法聚合；再以新样本验证。也可将全部既有完整样本分别做配对重放，报告结果随轨迹变化的范围，但这不能替代真实硬件验证或S8的真实门控执行。
