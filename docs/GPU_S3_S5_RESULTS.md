## S5-b / S6分段诊断

使用S5-a的8输出native核验轨迹做kernel清点：9032个节点中5668个包含kernel、3364个没有kernel，249个节点包含多个kernel；6112个kernel均落在某个节点回调窗口内。这只是已有CUPTI kernel记录的诊断，不能将每个节点都当作GPU计算段。

新增独立`gpu_s_transfer_probe`，在原native相同模型和输入下以timing模式记录CUPTI memcpy及memset。8个输出和完整logits与原native逐位一致、无CUPTI丢失。请求范围内记录330次传输或清零活动：其中250次完全处于单节点回调窗口，80次不完全处于任何单节点窗口；后者包括72次H2D和8次D2H，8个执行步各9次H2D及1次D2H。8次D2H均在各步最后节点之后、执行结束之前。该探针记录尚未将跨窗口或窗口外活动按实际stream依赖归属，也没有区分所有必要传输和插桩相关活动。

因此不能仅给每个回调或每个kernel机械添加1000ps，更不能忽略这80次活动形成S6完整计算表。该诊断据此要求建立能覆盖首段、跨窗口传输和尾段的互斥工作分段，核验相同执行序列及stream依赖，再接入S5-b固定值和S6重复采样。探针是诊断，并非S5-b通过或S6正式性能测量。
