# F1：第 10 层完整 FFN 权重联合实验

日期：2026-11-04。批次：`output/gpu-ffn/20261104-f1-001/`。**F1 已实现并实际运行通过。** 后续 [F2](GPU_F2_RESULTS.md) 与 [F3](GPU_F3_RESULTS.md) 均已完成。

## 条件与实现

Qwen3-0.6B F16 GGUF，模型 SHA256 `74878aba1d10648eae3d6cfef822f8c59ce3217b3808b35fce2dd02d975952a2`，RTX 5070，44-token 输入，greedy 生成 8 个非 EOS 输出；context/batch/ubatch=512/256/256，原生 GPU F16 KV，MUL_MAT 显式 F32，关闭 CUDA graphs 和 flash attention。

选区仅为 `blk.10.ffn_gate.weight`、`blk.10.ffn_up.weight`、`blk.10.ffn_down.weight` 三个完整 F16 矩阵，每个 6 MiB，合计 18 MiB。其 Global 起点为 180、186、192 MiB，来自完整 84 矩阵布局，后续扩大选区时可保持地址一致。FFN norm 及其他权重不接入本轮 HBF。

后端逻辑容量为 512 MiB，几何为 1 channel、1 die、2 banks、16 pages/block、4096 blocks/bank，页为 4096 B；其他时延、调度、缓冲和并行预算沿用原 H0。Host resident=256，MOCS=256，累计片段保护 10 亿，取消旧 1000 万事件截断。只普通写初始化登记的 18 MiB，初始化之后取请求 t0。

新增[独立运行入口](../README.md)，复用 S8 GPU 执行器并通过编译条件选择新的 gate 和分段实现；旧 S8 构建继续选择原实现。当前工作区源码在独立 `build-ffn/` 中编译，未覆盖历史封存构建。

一次 native 运行采集 18072 个同步窗口的 CUPTI GPU 活动，活动区间并集总计 61.983127 ms；冻结这一条轨迹后，一次 F1 联合运行执行实际 GPU 和 HBF 访问，使用同表推进模型时钟。CPU 发射空隙和后端软件耗时不加入该时钟。单条轨迹不代表生产性能或 GPU 时间分布。

## 实际软件成本

| 项目 | 实测 |
|---|---:|
| native 整进程 | 17.574 s |
| F1 整进程 | 423.418 s（约 7 分 3 秒） |
| 两次进程合计 | 440.992 s（约 7 分 21 秒，不含编译、清单生成和离线审计） |
| F1 后端初始化调用 | 0.339 s |
| F1 后端读调用及在线审计合计 | 405.408 s |
| F1 后端 finish 调用 | 0.000001 s |
| native 峰值进程 working set | 1724.508 MiB |
| F1 峰值进程 working set | 1754.867 MiB |

进程峰值是 Windows PeakWorkingSetSize 采样，不是 GPU 显存或系统 commit 总量。软件读调用耗时来自 CPU 上的离散事件模拟及在线审计，不能解释为真实硬件要花 405 秒读取 144 MiB。后端仍保留部分完成 Global/版本历史，不能由 observer 的有界活动表推断总内存恒定。

F1 的读调用软件吞吐约 0.355 MiB/s（约 5820 个 64 B 读片段/s）。后续软件预算应以此实测为起点，并在 F2 后修正；不能再沿用旧 10 KiB 案例或此前假设的每秒 1万—10万片段估算。
